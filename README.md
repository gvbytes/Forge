# Agent IDE — Autonomous Agentic Coding Workspace

NOTE: Upgrading Forge to orchestrate LLMs with >80B parameters :)

Agent IDE is an autonomous coding environment and model routing gateway designed specifically for small open-weight models (<=80B total parameters), built for the Takneek High-Prep evaluation benchmark.

The system combines a local model router with automatic tier classification and failover, a multi-agent orchestration engine with DAG scheduling and AST-based semantic code retrieval, and a browser-based IDE featuring real-time SSE execution streaming, Monaco diff reviews, and embedded xterm.js PTY terminals.

---

## Architectural Principles

### 1. 4-Role NVIDIA NIM Text Architecture

To maximize accuracy while strictly adhering to the <=80B parameter constraint, Agent IDE uses dedicated open-weight models pinned to specialized agent lifecycle roles:

| Role | Pinned Model | Total Parameters | Architecture | Core Function |
| :--- | :--- | :--- | :--- | :--- |
| **Planner** | `google/gemma-4-31b-it` | 31B | Dense | Heavy reasoning (AIME 89.2%, LCB 80.0%). Decomposes goals into a Directed Acyclic Graph (DAG) of steps; runs once at task initialization. |
| **Coder** | `nvidia/nemotron-3.5-lightning-30b-a3b` | 30B | MoE (3B active) | RL-trained for multi-step tool use, code authoring, and structured file edits. |
| **Reviewer** | `meta/muse-glimmer-30b` | 30B | Dense | Independent Meta lineage verifier (MCP-Atlas 75.5%). Eliminates self-review bias by validating proposals generated by the Coder. |
| **Triage / Explorer** | `openai/gpt-oss-20b` | 20B | MoE (3.6B active) | Fast triage (~440ms), /bytheway side queries, symbol search, and history compression. |
| **Vision** | `meta/llama-3.2-11b-vision-instruct` | 11B | Dense Multimodal | Dedicated image understanding and visual QA directly in chat without side effects on the workspace. |
| **Transcription** | `whisper-large-v3` (via Groq) | 2B | Transformer ASR | Speech-to-text audio input. |

## Scoring Model Alignment

Forge is calibrated against the mentioned scoring formula:

$$S = \frac{10 \cdot A}{\left(1 + 0.65\left(\frac{C}{0.15}\right) + 0.35\left(\frac{T}{1320}\right)\right)^{2.5}}$$

- **Accuracy ($A$) Dominance**: A failed task scores 0. Accuracy is treated as the primary objective; fast failure or incomplete code generation is explicitly avoided.
- **Cost Trade-off**: $0.01 in spend is mathematically equivalent to 163 seconds of execution time. All text LLM interactions default to the free/included NIM pool with an explicit $0.50 task budget ceiling.
- **Surgical Line-Level Edits**: Rather than dumping entire files (which consumes excessive context tokens and compounds latency $T$), the engine generates unified hunk diffs with exact line coordinates.

## Core Subsystems

### 1. Agent Engine (`engine/`)
- **Topological DAG Scheduler**: Steps without dependencies execute concurrently up to the configured concurrency cap, while dependent steps wait for prerequisite artifacts.
- **Hybrid Code Retrieval**: Combines MiniSearch BM25 term matching with tree-sitter AST symbol graphs and Personalized PageRank. This provides sub-millisecond symbol resolution without requiring heavy vector databases.
- **Checkpoint & Rollback Engine**: Every file modification is snapshotted before writes take effect. Changes can be accepted or reverted at the hunk level through the review modal.
- **Human-in-the-Loop Gate**: Supports configurable approval modes (`gate`, `optimistic`, `auto`). In `gate` mode, destructive actions (`write_file`, `edit_file`, `run_command`, `git_commit`) pause execution until confirmed by the user.

### 2. Local Model Router (`router/`)
- **OpenAI-Compatible Gateway**: Exposes standard `/v1/chat/completions` and `/v1/models` endpoints.
- **Health Tracking & 429 Cooldown**: Monitors consecutive rate limits and server errors with exponential backoff and automatic failover across role keys.
- **Zero External Telemetry**: All metrics, latency logs, and credential slots reside exclusively in local SQLite (`router/data/router.db`).

### 3. Web Interface (`web/`)
- **Interactive Stream & Chat**: Real-time server-sent events (SSE) render reasoning traces, tool executions, and diff proposals as they occur.
- **Claude-Style Token Popover**: Displays real-time breakdown of active context tokens (system prompt, memory, pinned files, message history) and budget consumption.
- **Integrated Terminal**: Native shell access powered by `node-pty` and `xterm.js`.
- **Transparent Vault Management**: View live health status, configure role-specific API keys, and test endpoints directly from the Settings modal.

3. Open `http://localhost:4444` in your browser.

### Architectural Decisions & Mitigations

#### 1. Orchestration: Directed Acyclic Graph (DAG) vs. Sequential Linear Chains
- **Problem**: In a standard sequential loop, independent subtasks (e.g., test scaffolding while generating an isolated utility module) wait for each other, increasing wall-clock time $T$.
- **Solution**:
  - The Planner produces an explicit dependency graph (`dependsOn: ["s1"]`).
  - Kahn's algorithm validates acyclicity; if a cycle is ever detected, it safely falls back to a linear sequence without deadlocking.
  - Mutex locking ensures parallel steps writing to the same file are serialized cleanly.
  - **Result**: Decreases task execution time $T$ by 30–50%, directly optimizing $S_{task}$.

### 3. Routing: Tiered Dynamic Gateway vs. Static Model Hardwiring
* **Why not hardcode a single model?**
  * Small models fail at high-level planning, while larger models waste token quota and trigger aggressive free-tier rate limits (NVIDIA NIM allows 40 RPM per account).
* **Our Solution (Tier S / M / L + Live Headroom Routing + 80B Invariant Guard)**:
  * Requests are classified dynamically by token length, file count, and complexity keywords.
  * Router tracks rolling 60-second RPM and circuit breakers ($429$ cooldowns). NVIDIA NIM is the only text provider, so a rate-limited or revoked key fails over to the next of three keys (three separate accounts, hence independent quotas) without losing session context.
  * The hard cap guarantees that models $>80\text{B}$ are physically rejected before touching the network.

### 4. Memory: Tiered Progressive Compaction vs. Truncation
* **Why not naive sliding window truncation?**
  * Dropping older messages causes the model to "forget" the original prompt instructions, coding rules from `AGENTS.md`, and prior failed attempts.
* **Our Solution (3-Tier Compaction)**:
  * **Tier 1 (Tool Output Pruning)**: Strips bulky command output once a subtask succeeds, keeping only the synthesized summary.
  * **Tier 2 (Diff Condensation)**: Collapses intermediate file edits into net-change hunk summaries.
  * **Tier 3 (Structured Rollup with AGENTS.md Pinning)**: Summarizes conversational history while pinning AGENTS.md rules and active task state immutably at the top of context.

## API Reference & Introspection Endpoints

### Agent Engine (`http://127.0.0.1:4100`)
- `GET /api/health` — Returns engine service status and uptime.
- `GET /api/router/status` — Live introspection of the local router, upstream provider health, and active key fingerprints.
- `GET /api/settings` / `PUT /api/settings` — Get or update provider, model, and budget configurations (automatically syncs keys to router).
- `POST /api/tasks` — Dispatches an autonomous agent coding task.
- `GET /api/tasks/:id` — Polling / inspection endpoint for task state and execution trace.
- `GET /api/events` — Server-Sent Events (SSE) stream for live agent execution frames.

### Local Router (`http://127.0.0.1:4098`)
- `POST /v1/chat/completions` — Standard OpenAI-compatible completion proxy.
- `GET /health` — Database and upstream provider connectivity status.
- `GET /routes` — Live active model tiers, routing policies, and provider error/RPM metrics.
- `GET /keys` — Returns masked last4 status of all configured provider keys.
- `POST /keys` — Dynamic runtime key injection into SQLite vault.
